세 시나리오 모두 같은 방식으로 장애를 만듭니다. manifests/deployment.yaml 을 Git에 실제로 커밋 → ArgoCD가 클러스터에 적용 → pod가 진짜로 실패합니다. 바꾸는 값만 다릅니다.

[oom — 메모리 한도 하향]

커밋 메시지 chore: 비용 절감 위해 메모리 limit 하향 (128Mi → 4Mi)

yaml
resources:
  requests: { memory: 4Mi }    # 128Mi → 4Mi
  limits:   { memory: 4Mi }

nginx가 기동하는 데 필요한 메모리보다 한도가 낮아서 컨테이너가 시작하다 커널에 죽습니다. 재시작을 반복하다 CrashLoopBackOff 로 갑니다.

에이전트가 봐야 하는 것

list_pods 의 last_terminated_reason: OOMKilled, last_exit_code: 137 입니다. 현재 로그는 비어 있습니다 — 컨테이너가 죽어서 새로 뜨는 중이라서요. get_pod_logs 를 previous=true 로 불러야 직전 컨테이너 로그가 나옵니다.

교육 포인트: "로그를 봤는데 아무것도 없다"에서 멈추면 안 된다는 것. 재시작 반복 시 어디를 봐야 하는지가 프롬프트에 들어가야 합니다.

[image-tag — 존재하지 않는 이미지 태그]

커밋 메시지 release: kdt-dev-api 1.29.0 배포

yaml
image: public.ecr.aws/nginx/nginx:1.290    # 실제로는 1.290 (오타)

레지스트리에 없는 태그라 이미지를 못 받아옵니다. pod가 Pending 에서 ImagePullBackOff 로 갑니다.

에이전트가 봐야 하는 것

get_events 의 Failed to pull image ... manifest unknown 입니다. 로그는 아예 존재하지 않습니다 — 컨테이너가 시작조차 못 했으니까요.

교육 포인트: 커밋 메시지는 1.29.0, 실제 태그는 1.290. 커밋 메시지는 '의도'일 뿐 '사실'이 아니라는 걸 보여주는 시나리오입니다. Git과 클러스터를 교차 확인해야만 원인이 보입니다. 세 개 중 가장 반응이 좋습니다.

[probe — readiness 경로 변경]

커밋 메시지 refactor: 헬스체크 경로를 /healthz 로 통일

yaml
readinessProbe:
  httpGet:
    path: /healthz    # / → /healthz

nginx에는 /healthz 가 없어서 404가 돌아옵니다. pod는 살아있지만 Ready가 안 되고, 롤아웃이 멈춥니다.

에이전트가 봐야 하는 것

get_events 의 Readiness probe failed: HTTP probe failed with statuscode: 404 입니다.

교육 포인트: 가장 어렵습니다. pod는 Running 이고 재시작도 없고 앱 로그도 정상입니다. 로그만 봐서는 절대 못 찾습니다. 이벤트를 봐야만 나옵니다.
