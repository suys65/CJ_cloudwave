# 56실습 (2부). Bedrock 자연어 SQL 생성과 Streamlit 시각화

> 1부에서 준비한 S3/Athena 데이터 위에서, 사용자가 한국어로 "카테고리별 매출 TOP 5 보여줘"라고 물으면 LLM이 SQL을 만들고 실제로 조회해 표·차트로 보여주는 앱을 구현한다. 이 글은 개념보다 **구현 구조·작동 원리·데이터 흐름**에 초점을 둔다.

## 전체 데이터 흐름

이 앱의 핵심은 데이터가 여러 AWS 서비스를 거치며 **형태가 계속 바뀌는** 것이다.

```
사용자 자연어 질문 ("월별 매출 추이 보여줘")
        │
        ▼
Streamlit 입력창                          [화면]
        │
        ▼
Bedrock Converse (nova-lite)              [자연어 → SQL 번역]
        │  프롬프트 = 테이블 스키마 + 규칙 + 질문
        ▼
생성된 SQL 텍스트
        │
        ▼
extract_sql() → validate_sql()            [코드펜스 제거 + 안전 검증]
        │  SELECT만 / 금지어 차단 / 허용 테이블만
        ▼
Athena start_query_execution()            [비동기 쿼리 시작]
        │  상태 폴링 (QUEUED→RUNNING→SUCCEEDED)
        ▼
결과 CSV가 S3에 저장됨                     [s3://버킷/athena-results/{쿼리ID}.csv]
        │
        ▼
S3 get_object() → pandas.read_csv()       [CSV → DataFrame]
        │
        ▼
Streamlit 표(st.dataframe) + Plotly 차트   [화면]
```

데이터 형태: **자연어 문자열 → SQL 문자열 → 쿼리 실행 ID → S3의 CSV → pandas DataFrame → 웹 화면**. 이 변환의 연쇄가 앱의 뼈대다.

## 작동 원리

### 1. 자연어 → SQL : 스키마를 프롬프트에 주입

질문만 주면 모델은 컬럼 이름도 매출 계산식도 모른다. 그래서 **테이블 구조를 프롬프트에 함께 넣는다.**
```
컬럼 목록과 의미 (order_date=주문일, region=지역 ...)
매출 계산식: (quantity * unit_price - discount_amount)
규칙: SELECT만, 변경문 금지, LIMIT 100, SQL 외 설명 금지
```
"매출"을 임의로 `SUM(unit_price)`로 계산하면 틀린다. 계산식을 명시했기에 `SUM(quantity*unit_price-discount_amount)`를 만든다. `temperature=0.0`이라 같은 질문엔 같은 SQL이 나온다.

### 2. SQL 추출 : 코드펜스를 벗긴다

모델이 SQL을 ` ```sql ... ``` ` 로 감싸면 `extract_sql()`이 정규식으로 안쪽만 꺼낸다. 없으면 응답 전체를 SQL로 본다.

### 3. SQL 검증 : 실행 전에 코드가 막는다 (가장 중요)

모델이 만든 SQL을 그대로 실행하면 위험하다("테이블 삭제해줘" 같은 질문). `validate_sql()`이 실행 직전에 검사한다.
```python
1. SELECT로 시작하지 않으면 → 차단
2. 금지 키워드(insert/update/delete/drop/alter/create/...) → 차단
3. 허용 테이블(ecommerce_sales)이 없으면 → 차단
```
프롬프트의 "SELECT만" 지시와 **이중 안전장치**다. 프롬프트는 유도일 뿐, 최종 차단은 코드가 한다. (실제로 DROP·DELETE·information_schema 조회가 전부 차단됨.)

### 4. Athena 실행 : 비동기 + 결과는 S3에

Athena 쿼리는 **바로 결과를 주지 않는다.** 이 비동기 특성이 `run_athena_query()`의 핵심.
```
start_query_execution()  → 쿼리 실행 ID만 반환 (결과 아님)
        │
반복: get_query_execution()으로 상태 확인 (1초 폴링)
      QUEUED → RUNNING → SUCCEEDED
        │
SUCCEEDED면 결과 CSV가 S3에 저장됨
        │
s3.get_object() → 문자열을 StringIO로 감싸 pandas.read_csv() → DataFrame
```
`StringIO`를 쓰는 이유: S3에서 읽은 CSV는 파일이 아니라 **문자열**이라, pandas가 파일처럼 읽게 감싸준다. `time.sleep(1)`은 상태 확인 API를 너무 빠르게 반복 호출하지 않기 위함.

### 5. Streamlit 시각화 : 컬럼을 축에 자동 매핑

DataFrame의 **첫 컬럼을 X축, 둘째 컬럼을 Y축**으로 잡아 차트를 그린다. 차트 유형(막대/선/파이)에 따라 Plotly 함수(`px.bar/px.line/px.pie`)를 고른다. 컬럼이 1개면(전체 매출 합계 등) 표만 보여준다. 전체를 `try/except`로 감싸 오류가 나도 앱이 죽지 않고 화면에 메시지를 띄운다.

## 관통하는 원칙

> **"SQL 생성은 LLM에게, 실행 여부 판단은 코드가."**

- LLM : 자연어를 SQL로 번역 (사람이 하던 일)
- 코드 : 그 SQL이 안전한지(SELECT만·허용 테이블만) 실행 전에 검증

앞선 실습들과 같은 철학이다. LLM은 실수하거나 악용될 수 있으니, 실제 실행(DB 쿼리) 직전에 코드가 한 번 더 막는다. 이 앱의 방어선이 `validate_sql()`이다.

## 조정하고 배운 것

**모델 ID** — `amazon.nova-lite-v1:0`은 이 리전에서 직접 호출이 안 되고 추론 프로파일이 필요해 `apac.amazon.nova-lite-v1:0`로 바꿨다.

**자격증명** — `.env`에 `AWS_PROFILE`을 지정하면 boto3가 자동으로 그 프로파일을 쓴다. 코드 수정 없이 프로파일을 붙일 수 있다.

**정수 나눗셈 함정** — "반품률"을 물었을 때 모델이 `SUM(...)/COUNT(*)`로 정수끼리 나눠 결과가 전부 0이 됐다. 프롬프트에 "비율 계산 시 100.0을 곱하거나 CAST(... AS double)"라는 규칙을 추가하니 정상 퍼센트가 나왔다. → **프롬프트에 계산 규칙을 얼마나 구체적으로 주느냐가 SQL 품질을 좌우한다.**

## 정리와 확장

전체 구조:
```
CSV → S3 → Athena 테이블  (1부)
   → Bedrock 자연어 SQL → 코드 검증 → Athena 조회 → pandas → Streamlit 시각화  (2부)
```

핵심은 **자연어와 데이터베이스 사이에 LLM을 번역기로 두되, 실행 전 검증으로 안전을 지킨다**는 것. 저장 대상(테이블)과 프롬프트만 바꾸면 다음으로 확장된다.
```
운영 로그 자연어 질의 도구
클라우드 비용 분석 챗봇
보안 이벤트 조회 시스템
관리자용 자연어 BI 대시보드
```
