# 56실습 (1부). S3 + Athena 데이터 분석 환경 구축

> 자연어 분석 앱(2부)을 만들기 전에, **LLM이 조회할 데이터 기반**을 먼저 준비하는 파트다. 로컬에서 샘플 CSV를 만들어 S3에 올리고, Athena 외부 테이블로 등록해 SQL로 조회되는 상태까지 만든다.

---

## 이 파트를 한 줄로

2부에서 "매출 보여줘"라고 물으려면, 그 매출 데이터가 **SQL로 조회 가능한 상태**로 어딘가에 있어야 한다. 1부는 그 상태를 만든다: **CSV → S3 → Athena 테이블 → SQL 조회**.

> 이 실습은 1부·2부로 나뉜 하나의 실습이다. 파일 번호도 1부 `01`·`02`에서 2부 `03`·`04`로 이어진다. 1부 = 데이터 준비, 2부 = 그 데이터를 자연어로 질의하는 앱.

---

## 관련 개념

### Amazon S3
원천 CSV 데이터와 Athena 쿼리 결과가 저장되는 오브젝트 스토리지. 이 실습에서 "데이터 창고" 역할.

### Amazon Athena
S3에 있는 파일을 **옮기지 않고 그 자리에서 SQL로 조회**하는 서비스. 서버를 띄우지 않고 쿼리당 스캔량으로 과금된다.

### AWS Glue Data Catalog
Athena의 데이터베이스·테이블 **메타데이터(스키마)** 를 저장하는 곳. "이 S3 경로의 CSV는 이런 컬럼 구조다"라는 정의가 여기 등록된다.

### 외부 테이블 (EXTERNAL TABLE)
데이터를 Athena 안으로 복사하지 않고 **S3 위치만 가리키는** 테이블. 즉 "S3의 CSV = 테이블"이다. 테이블을 지워도 S3 원본은 남는다.

### SerDe (Serializer/Deserializer)
Athena가 파일의 각 줄을 테이블의 행·컬럼으로 **해석하는 규칙**. CSV를 쉼표로 나눠 컬럼에 매핑하는 역할.

## 전체 흐름

```
로컬에서 샘플 CSV 생성          01_generate_sample_data.py
        │
        ▼
S3에 업로드                     02_upload_to_s3.py
   s3://버킷/datasets/ecommerce_sales/ecommerce_sales.csv
        │
        ▼
Athena 외부 테이블 등록          athena_create_table.sql
   (S3 경로를 가리키는 테이블 정의)
        │
        ▼
SQL 조회 테스트                  COUNT / SUM / GROUP BY
```

## 구현 구조 (파일별 역할)

| 파일 | 역할 |
| --- | --- |
| `01_generate_sample_data.py` | 가상 전자상거래 주문 데이터(CSV) 생성 |
| `02_upload_to_s3.py` | 생성한 CSV를 S3에 업로드 |
| `athena_create_table.sql` | Athena DB·외부 테이블 생성 DDL |
| `.env` | 리전·버킷·경로·DB·테이블 이름 설정 |

설정값을 `.env`로 분리하는 이유: 사람마다 S3 버킷 이름이 다르므로, 코드를 고치지 않고 설정만 바꿔 재사용하기 위해서다.

## 작동 원리

### 1. 샘플 데이터 생성 — 재현 가능하게

`random.seed(42)`로 난수를 고정해, 실행할 때마다 **똑같은 데이터**가 나온다. 2026년 1월 1일부터 90일간 하루 20~45건씩, 총 약 3천 건의 주문을 만든다. 컬럼은 12개(주문ID·주문일·지역·카테고리·수량·단가·할인·반품여부 등)이고, 문자열 값에는 **콤마를 넣지 않는다**(CSV 구분자와 충돌 방지).

매출은 이 공식으로 계산한다 — 2부에서 LLM에게도 이 식을 알려준다.
```
매출 = quantity * unit_price - discount_amount
```

`is_returned`는 `True/False`를 CSV에 `true/false`로 저장한다. Athena에서 boolean으로 읽기 위해서다.

### 2. S3 업로드 — prefix로 경로를 만든다

`.env`의 `DATA_PREFIX`(`datasets/ecommerce_sales/`)와 파일명을 합쳐 S3 객체 키를 만든다.
```
key = datasets/ecommerce_sales/ecommerce_sales.csv
```
S3는 실제 폴더가 없고 **키(경로 문자열) 기반**이라, 이 키가 콘솔에서 폴더처럼 보인다. `rstrip('/')`로 슬래시 중복을 막는다.

### 3. Athena 외부 테이블 — S3를 테이블로 연결

DDL의 핵심 세 가지:
```
CREATE EXTERNAL TABLE ...        S3 파일을 참조하는 테이블
LOCATION 's3://버킷/datasets/ecommerce_sales/'   데이터 위치
TBLPROPERTIES ('skip.header.line.count'='1')     첫 줄(헤더)은 건너뜀
```
데이터를 복사하지 않고 S3 경로만 가리키므로, 나중에 CSV를 교체하면 테이블도 자동으로 새 데이터를 읽는다.

### 4. 조회 테스트 — 데이터가 살아있는지 확인

```sql
SELECT COUNT(*) FROM ecommerce_sales;                         -- 전체 건수
SELECT SUM(quantity*unit_price-discount_amount) ...;          -- 전체 매출
SELECT category, SUM(...) GROUP BY category ORDER BY ... DESC; -- 카테고리별
SELECT date_format(order_date,'%Y-%m'), SUM(...) ...;         -- 월별
```
이 쿼리들이 성공하면 2부의 앱이 조회할 기반이 준비된 것이다.

## 교안 DDL에서 고친 것 — OpenCSVSerde의 날짜 함정

교안 원본 DDL은 **OpenCSVSerde**를 쓰는데, 이 SerDe는 `date` 컬럼을 ISO 문자열('2026-01-01')이 아니라 **숫자(UNIX epoch)로만** 해석한다. 그래서 월별 매출처럼 날짜 함수를 쓰는 쿼리가 실행되면 실패한다.
```
BAD_DATA: NumberFormatException: For input string: "2026-01-01"
```
COUNT·SUM·카테고리별 집계는 되지만, `date_format(order_date, ...)`에서 터진다. 이 데이터는 필드에 콤마·따옴표가 없으므로, ISO 날짜를 date로 올바르게 파싱하는 **LazySimpleSerDe**(`ROW FORMAT DELIMITED FIELDS TERMINATED BY ','`)로 바꿨더니 월별 쿼리까지 전부 동작했다. → **SerDe 선택이 컬럼 타입 해석을 좌우한다.**

## 정리

1부에서 만든 것: **S3에 올라간 CSV + 그것을 가리키는 Athena 외부 테이블 + SQL로 조회되는 상태.**

```
CSV 생성 → S3 업로드 → Athena 외부 테이블 → SQL 조회 성공
```
